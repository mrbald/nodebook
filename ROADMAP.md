# Nodebook roadmap

This page tracks open product and engineering work. For features you can use in this checkout, see the [user guide](src/renderer/src/help.md). For packaged versions, see [GitHub Releases](https://github.com/mrbald/nodebook/releases).

## Help new readers get started

- Introduce links, properties, backlinks and maps in a new vault. Today the empty-vault screen offers a way to create the first note.
- Give Settings a form for common changes while keeping the TOML editor available.
- Explore a quick-open or command palette. The current shortcuts include Find Note and Print.
- Extend search to queries about properties and relationships, such as finding notes with `status:: active`.

## Keep maps useful as a vault grows

A saved `.map.md` outline can be opened today. Saving the current graph, including its focus, filters and placements, needs a file format that can restore those choices after notes change. [Maps and saved outlines](docs/mindmap-mode.md)

For large graphs, measure the cost of drawing and arranging the visible notes before choosing a new algorithm. Possible approaches include collapsing a group into one node, skipping off-screen detail, and approximating distant forces with Barnes–Hut. Compare community detection or spectral layouts with the current layouts on the same graph. The [layout trials](docs/quality-trials.md) give a starting point.

Other proposals include names for vault themes generated by a model, suggestions for missing links, and a semantic layout based on distances between note vectors. Evaluate whether readers can identify and follow a useful connection before adopting them. [Automatic map structure](docs/auto-mindmap.md)

## Combine evidence from several books

Merge suggests notes that might describe the same idea. When a reader confirms a match, the side panel shows citations from both files. Open questions include how to consolidate those citations in one Markdown file, keep familiar groups stable after an update, and show what changed before a reader accepts it. Test these decisions on a vault with several sources and record its size. [Knowledge across sources](docs/body-of-knowledge.md)

## Evaluate imports and local models

- Establish a repeatable real-provider quality check alongside the offline distill evaluation. Track how many target concepts appear and whether the sources support each relationship. [Book import measurements](docs/distill-documents.md) · [Quality trials](docs/quality-trials.md)
- Revisit running a chat model inside Nodebook if users need offline chat without a separate local service. That option would require per-platform packaging, a model download and model management. Ollama and compatible local endpoints work today. [Search and chat](docs/talk-to-docs.md)

## Maintain the desktop app

- Consider automatic updates from GitHub Releases. Users currently download new builds.
- Bring the file tree and saved-map tree controls into closer agreement.
- Replace remaining non-null assertions in native dialog calls when changing window lifecycle code.
